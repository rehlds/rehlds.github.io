# 支持的游戏

社区中的热心成员梳理了几个知名的 _Metamod_ 版本：

* [metamod (Original)](https://sourceforge.net/projects/metamod/files/Metamod%20Sourcecode/1.20/) ("games.h"), 
* [metamod-p](https://github.com/jkivilin/metamod-p/blob/master/metamod/games.h), 
* [metamod-p-cmake](https://github.com/SamVanheer/Metamod-P-CMake/blob/master/metamod/games.h) （只是一个分支，针对 CMake 构建做了优化）
* [metamod-am\metamod-hl1](https://github.com/alliedmodders/metamod-hl1/blob/master/metamod/games.h)，来自 [alliedmodders](https://github.com/alliedmodders/)。
在此基础上整理出一份清晰且实时的模组清单，（**`粗略地*`**）验证了运行情况，并让 **[Metamod-r](https://github.com/rehlds/metamod-r)** 开箱即支持这些游戏。

## Known Issues

### SvenCoop

#### 「预缓存上限 — 512」
![image](https://user-images.githubusercontent.com/34998786/37242681-89c5da6a-24a8-11e8-8ef2-97188b70a6f3.png)

该游戏修改了引擎和客户端预加载对象的上限。由于 metamod-r 需要 rehlds，服务端的上限被改回标准的 512 个对象。结果是，超出该上限的地图无法运行（单人地图上的合作模式）。但与此同时，`crossfire` 之类的标准联机地图可以正常工作。（_这并不是 [metamod-r #29](https://github.com/rehlds/metamod-r/issues/29) or [rehlds #591](https://github.com/rehlds/ReHLDS/issues/591), 的缺陷，但会受其影响_。）

##### 如何修复：
* 尝试把 `steam` 版本更新到 svencoop 的 [Build 3082297](https://forums.svencoop.com/showthread.php/45308-Sven-Co-op-Update-Released-Build-3082297) 。

> 已恢复与原版 GoldSrc／Metamod-P 的 API/ABI 兼容性。为 Sven Co-op 定制的 Metamod-P 构建不再需要（实际上也已无法使用）。

##### 变通办法：
* 尝试使用 ![](https://i.imgur.com/AzhAYR4.png) [metamod_unprecacher](https://github.com/In-line/metamod_unprecacher) 或类似工具来屏蔽未使用的资源。`未经测试`
* 尝试自行构建一个提高了上限的 rehlds，以匹配 svencoop 的需求。`未经测试`
