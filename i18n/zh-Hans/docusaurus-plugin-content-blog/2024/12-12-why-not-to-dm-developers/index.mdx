# 为什么不要私信开发者

开源开发者每天都会收到来自用户的问题和困扰。但你知道吗，通过私信提问，远不是获得答案的最佳方式。事实上，很多问题在公开渠道讨论时，解决得要快得多、也高效得多。这既适用于 ReHLDS 项目，也适用于许多其他开源项目。

当你私信提问时，问题就停留在了「暗处」——只有你和那位开发者知道它的存在。而把问题或缺陷发到 GitHub Issues 或 GitHub Discussions 上，不仅开发者能看到，社区中的其他成员同样可以帮你找到解决办法。毕竟，开源社区运转的基础正是互助与知识共享。参与解决问题的人越多，它被解决得就越快。

## 为什么要发到 GitHub 上，而不是私信？

开发者都很忙。每回复一条私信，都会占用本可以用来修缺陷、加新功能或做性能优化的时间。在开发者花时间了解你的问题时，其实别的用户可能早就能给出答案了。

为什么这一点很重要？

1. **公开讨论**：当一个 issue 或问题被公开，其他用户就能分享他们的解决办法或建议。这会形成积极的协作氛围。
  
2. **公开可见**：所有人都能看到你的问题并帮你寻找答案，这大大提高了问题被迅速解决的可能性。

3. **节省资源**：开发者的时间有限，应当集中用于更大、更复杂的问题，而不是处理那些在公开空间就能解决的简单情况。

## 开源中沟通的有效性

GitHub Issues 和 Discussions 这类平台，本就是为用户与开发者讨论项目及其问题而设计的。需要理解的是，终端用户并不总能客观判断问题的规模。有时看起来像是严重缺陷的东西，实际上只是一次误解或一处安装错误。正因如此，公开讨论能帮助项目的所有参与者评估问题的真实重要性，并尽可能快地把它解决掉。

## 如何在 GitHub 上提问

1. 写具体：描述导致错误的操作步骤。
2. 给背景：说明你使用的系统以及相关的版本。
3. 附日志：这能显著加快诊断与解决的速度。

与其私信，不如创建一个带有详细问题描述的 issue。这不仅能加快解决速度，也能让你免于无谓的等待和不确定。

## 为项目做贡献

请记住，每一个发在公开渠道的问题或消息——无论是在 GitHub 上的讨论，还是在聊天群里——都是对项目发展的贡献。这比单纯的私信交流要有价值得多。公开渠道有助于形成一个社区，让知识和想法的流动比在私信里快得多。
