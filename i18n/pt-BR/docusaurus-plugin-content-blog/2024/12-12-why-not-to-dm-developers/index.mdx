# Por que você não deve mandar DM para os desenvolvedores

Todos os dias, os desenvolvedores de código aberto recebem perguntas e problemas dos usuários. Mas você sabia que mandar perguntas por mensagem direta está longe de ser a melhor forma de obter uma resposta? Na prática, muitos problemas são resolvidos bem mais rápido e de maneira mais eficiente quando discutidos em canais públicos. Isso vale para o projeto ReHLDS e para muitas outras iniciativas de código aberto.

Quando você manda uma DM, o problema fica "nas sombras". Só você e o desenvolvedor sabem dele. Publicar uma pergunta ou um bug nas GitHub Issues ou nas GitHub Discussions permite que não apenas o desenvolvedor, mas também outros membros da comunidade, ajudem você a encontrar uma solução. Afinal, a comunidade de código aberto funciona com base na ajuda mútua e na troca de conhecimento. Quanto mais gente envolvida na solução do problema, mais rápido ele será resolvido.

## Por que publicar no GitHub em vez de mandar DM?

Desenvolvedores são pessoas ocupadas. Cada resposta a uma mensagem direta tira tempo de tarefas como corrigir bugs, acrescentar recursos ou otimizar o desempenho. Enquanto o desenvolvedor gasta tempo reunindo informações sobre o seu problema, outros usuários poderiam estar oferecendo uma solução.

Por que isso importa?

1. **Discussões abertas**: quando um problema ou uma pergunta se torna público, outros usuários podem compartilhar soluções ou sugestões. Isso cultiva um clima ativo de colaboração.
  
2. **Visibilidade pública**: todos podem ver a sua pergunta e ajudar você a encontrar uma solução, o que aumenta bastante a chance de uma resolução rápida.

3. **Economia de recursos**: o tempo dos desenvolvedores é limitado e deve se concentrar em questões maiores e mais complexas, e não em resolver casos simples que poderiam ser tratados em espaços públicos.

## A eficácia da comunicação no código aberto

Plataformas como as GitHub Issues ou as Discussions existem para que usuários e desenvolvedores discutam os projetos e os problemas deles. É importante entender que os usuários finais nem sempre conseguem avaliar objetivamente a dimensão de um problema. Às vezes, o que parece um bug crítico é, na verdade, um simples mal-entendido ou um erro de instalação. Por isso, as discussões abertas ajudam todos os participantes do projeto a avaliar a real importância de um problema e a resolvê-lo o mais rápido possível.

## Como fazer perguntas no GitHub

1. Seja específico: descreva os passos que levaram ao erro.
2. Dê contexto: informe o sistema que você usa e as versões envolvidas.
3. Anexe os logs: isso acelera bastante o diagnóstico e a resolução do problema.

Em vez de mandar uma DM, abra uma issue com uma descrição detalhada do problema. Isso não só acelera a resolução, como também poupa você de esperas e incertezas desnecessárias.

## Contribuindo com o projeto

Lembre-se: toda pergunta ou mensagem em canais públicos, seja em uma discussão no GitHub ou em um bate-papo, é uma contribuição ao desenvolvimento do projeto. Isso é muito mais valorizado do que uma conversa por DM. Os canais públicos ajudam a criar uma comunidade em que o conhecimento e as ideias circulam mais rápido do que circulariam em mensagens privadas.
